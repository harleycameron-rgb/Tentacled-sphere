# OATH_FACE_TEMPORAL_RELEGATION_V1

**Purpose:** Facial melting represents trajectory-caused generative replacement, making way for emerging topology while relegating rejected claims to a referencable past.

## Boundary

1. The existing StructuralMeltingConsumer controls assembly, separation, trajectory plotting and attachment. The new module does not alter its state machine.
2. The trajectory deformation adapter describes visual displacement only. No pixel deformation, melting, or visual disappearance is evidence of falsity.
3. A separate evaluator supplies a semantic classification with references to method, decision and evidence. This module **validates and records** that classification; it does not independently establish its correctness.
4. Four states must remain distinct: supported, unsupported, disproven, unknown. Unsupported is not disproven. Only **disproven** warrants the term false, and only to the extent justified by the referenced evaluation.
5. Unsupported and disproven claims become non-authoritative, referencable-past records; unknown remains unresolved; supported remains active. Requalification requires a separately evaluated new record, not retroactive mutation.
6. Records include logical tick, claim, separation and trajectory identifiers and evidence references only. Never store selfie frames, biometric features, or raw personal information in the ledger.
7. All outputs are local research classifications: `liveGate=CLOSED`, `receiptTrust=UNVERIFIED`, `sphereWrites=false`.

## Integration not yet implemented

No automatic connection to a real evaluator, persisted history, original selfie renderer, or eight-app UI. Caller must authenticate the external evaluator, enforce monotonic tick history, verify separation/attachment from the authoritative state machine, and control retention/privacy. The flags accepted by the current pure function do **not** prove any of those conditions.

## Acceptance tests

Four-state mapping, unsupported/disproven distinction, unknown preservation, evidence-reference validation, CLOSED-gate rejection, attachment guard and determinism. Test file is authored; execution status must be reported separately.

No merges, deployment or native firing authorised.
